## 安全策略和 Work 2 边界

推荐 Schema 仅允许 `manual_review/NONE` 与 `baseline_get/GET`，必须绑定对应 Subject URL。策略检查 Scope、已知端点、Method 与剩余预算。所有建议均 `executed:false`、`requiresApproval:true`。

本轮没有实现推荐动作的执行入口。未来执行必须取得授权，并再次走同一 Run 的 HttpClient / Scope / Budget / Rate Limiter。Mock Provider 没有探测权限。

未来 Pro gate 的稳定接入位置是配置开关和 `AITriageEngine::Run` 之前；商业负责人决定功能边界。未实现 Paddle、订阅数据库或付款判断，未修改 Work 2 授权模块。

## 尚未完成及风险

1. 引用校验保证事实和 Subject 的来源关系，无法证明自然语言风险推测正确；报告明确标为未验证的 Provider hypothesis。
2. 正文只保留 SHA-256，不保存原文；需要完整业务响应证据时仍需人工采集。脱敏不是通用秘密识别器，真实外部 Provider 需要单独的数据披露设计。
3. Context 限于 64 Subjects、每项 4 个支持快照、每端点 16 个参数类型/风险因素。完整库存/证据仍在报告；大项目可能只获得部分 Triage。
4. Provider 截止时间会停止等待并发出取消信号；C++ 无法安全强制终止不合作的线程。未来网络 Provider 必须自行实现取消和 I/O 超时。
5. HTTP 超时是 WinHTTP 阶段配置，不是整个审计的墙钟总期限。Scope、预算与速率限制仍在实际发送入口。
6. Probe 名称表示复核意图；现阶段是受控 baseline GET，没有自动 IDOR/SQLi/XSS 验证或账号切换。
7. 已验证本机和独立源码目录，未完成无 Visual Studio 的全新 Windows 系统验收。商业发布仍需该安装体验检查和真实用户试用。
