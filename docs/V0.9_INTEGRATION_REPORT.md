## Client integration decisions

- `Application/main.cpp` remains the single Windows/UTF-8 entry point. It dispatches
  `--auth login|status|check|logout` first; a normal audit falls through to `CLI::Run`.
  No second authorization dispatch or subscription gate was added to the audit path.
- `Interface/cli.cpp` now documents both command families and explains that account
  commands run separately. AI flags, configuration priority and project compatibility
  remain unchanged. Credentials are not audit configuration or persisted project data.
- `RABBITX.vcxproj` and its filters already include both entitlement implementation
  files and the AI engine/provider. x64 Debug/Release use C++17, Release uses `/MT`,
  and the conditional native test entry point does not conflict with `wmain`.
- Mock triage stays optional and offline. `pro-foundation` remains an online diagnostic
  gate. No existing Free feature is moved behind a paid check.
- Paddle, Worker, D1 migrations and production configuration are not modified by
  the integration commit. Concurrent commercial backend/document edits are excluded.

## Repeatable verification

Use PowerShell 7, VS 2022 C++ tools and Node.js 24+:

```powershell
pwsh -NoProfile -File .\tools\test-integration.ps1
# If MSBuild needs an explicit path:
pwsh -NoProfile -File .\tools\test-integration.ps1 `
  -MSBuildPath 'D:\VS\MSBuild\Current\Bin\MSBuild.exe'
```

The runner builds both product configurations, runs the original product and
authorization suites, and adds CLI coexistence checks against each normal product
executable. The new checks exercise all four auth command routes with invalid mixed
arguments, which must fail before credential access or an account request. Actual
sign-in, entitlement and logout state transitions are covered by the original
native authorization tests using an injected transport and in-memory token store.
The tests do not execute a live sign-in, read/delete the user's saved credential,
contact Paddle/email services, deploy a Worker, or access production D1.

Free project save/resume, configuration overrides, offline replay, JSON/HTML and
Mock triage are checked without sign-in. With budget zero, Mock returns `no_evidence`
and sends no requests; nonempty evidence-backed Mock results are exercised by the
original local fixture suite. Recommendations never execute target requests.

## Remaining limits

- AI results are **Mock only**, not real model analysis. No real AI provider is enabled.
- Authorization state transitions are tested with mocks. Production email, live
  subscription verification and successful real account sign-in are not tested here.
- No new AI paid-feature ID or Free/Pro product boundary is introduced. A future
  commercial AI gate needs the product owner's decision and a server contract.
- No formal GitHub Release or production deployment is part of this integration.
